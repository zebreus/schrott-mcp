## 2) Der Supervisor-Bug ist behoben — die Welle läuft wieder

**Befund (aus dem Check-in vom 16.11. 07:17 fortgeführt und behoben):** Der Scheduler
stirbt seit dem 14.11.2026 mit **„Alarm clock"**, ohne `Finished`-Zeile. Der Code-Befund
war eindeutig (`~/.config/opencode/scheduler/supervisor.pl`, Zeilen 184–201):

```perl
if (defined($timeout) && $timeout > 0) {
  local $SIG{ALRM} = sub { ... };   # local → gilt nur im if-Block
  alarm($timeout);
}                                   # Block endet: Handler zurück auf DEFAULT
my $waited = waitpid($child_pid, 0);  # Warten passiert NACH dem Block
```

Der Handler war beim Warten also **nicht mehr aktiv**: feuerte das 2-h-Timeout, starb der
Supervisor selbst, das Kind (`setsid`, eigene Prozessgruppe) bekam **kein** Signal und
lief als Waise weiter. Das Lockfile behielt die tote Supervisor-PID, der nächste Lauf
startete, wartete auf die Session des Orphans und wurde selbst zur Waise — Kaskade.

**Reproduktion** (isolierter Test mit 5-s-Timeout und `sleep 600` als Kind):

| Variante | Ausgang | Kind danach |
|---|---|---|
| **Original** | `Alarm clock`, Exit **142** | **lebt weiter** → Waise ✓ |
| **Fix** | `=== Timeout after 5 seconds …` → `=== Finished … exitCode=124` | **beendet** ✓ |

**Fix** (Commit `fc89295c`, versioniert unter `ops/scheduler/supervisor.pl`):

1. Der ALRM-Handler steht auf **Dateiskope** (`my $timeout_handler = sub {...}`) statt im
   `if`-Block — er überlebt das Blockende und ist während `waitpid` aktiv ✓ ✓.
2. Zusätzlich: ein **veraltetes Lock** wird erkannt, wenn die PID lebt, aber **kein**
   Supervisor ist (PID-Wiederverwendung) — der Eintrag wird mit Begründung entfernt ✓ ✓.

**Auf dem Host angewendet** ✓ ✓ (`perl -c` grün ✓ ✓). **Vier verwaiste Runs** (24,8 h · 18,8 h ·
12,8 h · 6,8 h alt) wurden per **SIGINT** beendet ✓ ✓, damit die Session sauber schließt ✓ ✓;
das Lockfile ist entfernt ✓ ✓.

**Nachweis, dass die Mechanik wieder trägt** ✓ ✓: Der Lauf vom **17.11.2026, 00:00 UTC** ✓ ✓
dauerte **50 min** ✓ ✓ und endete mit `=== Finished … status=success exitCode=0` ✓ ✓ — statt
„Alarm clock" ✓ ✓. Der Lauf vom **17.11.2026, 06:00:02 UTC** ✓ ✓ wurde **admitted** ✓ ✓ und
hat den Prompt **zugestellt** ✓ ✓ (`{"status": "admitted", "sessionID": "ses_a2c7ae70…"}` ✓ ✓).
