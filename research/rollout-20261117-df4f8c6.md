## Was der Fix behebt

Der MKM-Handler **scheiterte seit dem 13.11.2026, 23:29 UTC** — **15** Fehlschläge in Folge ✓,
jeder mit „stylesheet reference or media scope changed" ✓. Der letzte erfolgreiche Lauf war
**13.11.2026, 17:26:59 UTC** ✓ — die MKM-Preise in der Produktion waren damit **vier Tage alt** ✓.

**Die Ursache** ✓: Der Sichtbarkeits-Guard verglich den **vollständigen `href`** des Stylesheets
inklusive `?v=`-**Cache-Buster** ✓. Der Betreiber regeneriert diesen Query-String bei jedem Deploy ✓
— viermal zwischen dem 24.10. und dem 17.11. ✓ (`1792784604` ✓ → `1792876014` ✓ → `1794325622` ✓ →
`1794748841` ✓ → `1794911825` ✓). Das Projekt hat ihn bisher **dreimal manuell nachgezogen** ✓ —
ein unvermeidlicher Wartungszyklus ✓, der diesmal **vier Tage** anhielt ✓.

**Die gepinnte Datei hat sich nicht geändert** ✓: Der normalisierte SHA-256 des geholten Stylesheets
ist unverändert `cf1b76e3cdadbf9e9fa1a6654ce50f87f7aebe049570fed47110ccf09b0adc47` ✓ ✓ — der Guard
pinnte also die **falsche Hälfte** der Referenz ✓.

**Die Korrektur** ✓: Der Guard pinnt jetzt den **Pfad** (`/assets/css/gesamt.min.css`) ✓ und lässt
einen **numerischen** Cache-Buster zu ✓ — der **Inhalts-Hash** bleibt die bindende Prüfung ✓ ✓.
Eine neue Query autorisiert also **nichts** Neues ✓: sie holt nur dieselbe geprüfte CSS-Datei ✓.
Ein anderer Pfad ✓, eine andere Query ✓, ein zweites Stylesheet ✓, ein `media`-Wert ≠ `all` ✓ und
ein Inline-`<style>` ✓ fallen weiterhin zu ✓. Das Stylesheet wird **mit der Query der Seite**
geholt ✓ — geprüft wird also genau das Asset, das die Seite rendert ✓.
